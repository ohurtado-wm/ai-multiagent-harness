# Plan — Harness: AI-first repository

Root plan of the agent harness: why it exists, the decisions behind it and how to extend it. The explanation for people lives in [`HARNESS.md`](../../../HARNESS.md); this plan only records the decisions, so later harness plans (`parent: PLAN_HARNESS.md`) have somewhere to hang from.

## Owner decisions

| Topic | Decision |
|---|---|
| Source of rules | **`AGENTS.md` is the only source.** `CLAUDE.md` only imports it, so Codex and Claude read the same rules. |
| Branches | **Work branch → `dev` → `main`.** Agents never commit, push or open PRs to `main`; a person promotes `dev` to `main`. |
| Plans | **A plan before any feature.** The plan header holds the real status; GitHub issues are thin and only open or closed. |
| Who writes and who reviews | **Codex writes the code, Claude reviews it.** Inside a team, nobody approves their own work. |
| Who talks to the person | **Only the coordinator** asks the person and only the coordinator commits. A message from another agent is never permission. |
| Cost | **The coordinator on the most capable model, teammates on a cheaper one**, plans read by line ranges, reports in a file, waiting without polling. |
| Slow tests | **Regression tests only with an explicit yes** per batch. |
| Findings | **Fixed in the same PR by default**; leaving one out is the owner's call and becomes a GitHub issue. |

## Extending it

- New rule that must not depend on the agent's memory: add it to `AGENTS.md` and, if it can be checked mechanically, to a hook with its test.
- New generated file: add it to `CONFIG` in `.claude/hooks/generated-guard.mjs`.
- New area or toolchain: `areas_of` and an `area_*` function in `scripts/verify.sh`, its test in `scripts/verify.test.mjs`, a job in `.github/workflows/ci.yml`.
- New role: a file in `.claude/agents/`, its brief in `.claude/skills/orchestrate-team/briefs.md` and, if it must be restricted, a rule in `team-guard.mjs`.
